# nagramxf-mirror

Зеркало CI-сборок [Nagram XF](https://github.com/Keeperorowner/NagramXF) в нормальные
GitHub Releases, чтобы их можно было отслеживать через
[Obtainium](https://obtainium.imranr.dev/).

**Этот репозиторий ничего не собирает.** Он забирает артефакт, который собрал CI
оригинального репозитория, проверяет его подпись и публикует один APK как релиз здесь.
Байты приложения не изменяются и не переподписываются.

## Зачем это нужно

- Последний релиз в оригинале — `12.10.1.1251` от 14.09.2026, а в ветке `dev` уже `13.2.1`.
- Джоба автопубликации в оригинальном workflow закомментирована, а `permissions: contents: read`
  не даёт ему создавать релизы в принципе.
- Telegram-каналы оригинала тоже встали: стабильный — 14.09.2026, бета — 05.10.2026.
- Единственный живой выход — артефакты GitHub Actions: ZIP на 253 МБ с четырьмя APK,
  доступный только залогиненным пользователям GitHub. Obtainium за таким следить не умеет.

Этот репозиторий превращает этот ZIP в один `.apk`-ассет на 59 МБ в обычном релизе.

## Почему это отдельный репозиторий, а не форк

1. **В форках запланированные воркфлоу выключены по умолчанию** (состояние `disabled_fork`).
   Вся схема держится на расписании — в форке она молча не запустится.
2. **Форки не синхронизируются сами.** «Sync fork» — всегда ручное действие. А здесь
   синхронизация и не нужна: свежесть обеспечивает оригинальный репозиторий,
   из CI которого берутся байты.
3. Форк тащит сотни мегабайт исходников Telegram, а «Sync fork» конфликтует
   с коммитами `state.json`, которые делает этот воркфлоу.

## Установка

```bash
# 1. Создайте НОВЫЙ ПУБЛИЧНЫЙ репозиторий (public = безлимитные минуты Actions)
#    например nagramxf-mirror

# 2. Скопируйте содержимое этой папки в него, чтобы получилось:
#      .github/workflows/republish.yml
#      .github/workflows/keepalive.yml
#      tools/extract_from_remote_zip.py
#      tools/verify_signer.py
#      state.json
#      README.md
#
#    ВАЖНО: republish.yml должен лежать в ВЕТКЕ ПО УМОЛЧАНИЮ.
#    GitHub читает расписание `schedule:` только оттуда.

git clone https://github.com/<ваш-логин>/nagramxf-mirror.git
cd nagramxf-mirror
# ...скопируйте файлы...
git add -A
git commit -m "ci: mirror upstream NagramXF Actions builds into releases"
git push
```

3. Вкладка **Actions** → включите воркфлоу, если GitHub спросит.
4. **Mirror upstream NagramXF build** → **Run workflow** (дефолты: `staging` /
   `normal` / `normal-arm64-v8a\.apk$` / `rolling_tag=false`).
5. Через 3–5 минут появится релиз вида `ci-13.2.1-37a3538-20261117143000`.

### Настройка Obtainium

**Add App** → `https://github.com/<ваш-логин>/nagramxf-mirror`

| Параметр | Значение |
|---|---|
| Include prereleases | **вкл** (релизы помечаются как prerelease) |
| Verify latest tag | выкл |
| Filter APKs by regular expression | `arm64-v8a\.apk$` |
| Sort method | по дате (по умолчанию) |
| Background update checking interval | на ваш вкус, по умолчанию 6 часов |
| Download only over Wi-Fi | **вкл** (59 МБ на сборку) |

Псевдо-версионирование **не нужно**: каждая сборка — отдельный релиз со своим тегом.

### Если хотите полностью тихую установку

Поставьте [Shizuku](https://shizuku.rikka.app/) (на Android 11+ активируется прямо
с телефона через «Беспроводную отладку»), в Obtainium выберите способ установки
**Shizuku** и включите фоновые обновления.

Рекомендую при этом выставить **Minimum age for updates** (Obtainium ≥ 1.6.17)
часа на 3–6: это `dev`-ветка, и если в свежей сборке есть регрессия, о ней обычно
успевают написать в issues оригинала.

## Что делает воркфлоу

```
CI оригинала собирает 4 APK → GitHub пакует в ZIP (253 МБ)
                    ↓
   extract_from_remote_zip.py читает из этого ZIP только один APK (59 МБ)
   точечными HTTP Range-запросами: EOCD → central directory → байты файла.
   Остальные три ABI и universal не скачиваются вообще.
                    ↓
   verify_signer.py сверяет сертификат подписанта с эталоном.
   Не совпал → job падает, ничего не публикуется.
                    ↓
   сравнение SHA-256 с state.json: сборка не менялась → выходим
                    ↓
   gh release create  →  один .apk как ассет релиза
                    ↓
   Prune: хранятся последние 20 релизов, остальные удаляются
```

Расписание — каждые 30 минут (`13,43 * * * *`). Публичные репозитории получают
безлимитные минуты на стандартных раннерах GitHub, так что это бесплатно.
Холостой прогон стоит один API-запрос: шаг «изменилось ли?» отрабатывает до публикации.

`keepalive.yml` дважды в месяц делает пустяковый коммит. Это защита от правила GitHub:
в публичном репозитории scheduled-воркфлоу отключаются после 60 дней без активности,
причём **собственные запуски воркфлоу активностью не считаются**.

## Проверка подписи

Артефакты оригинала подписаны тем же ключом, что и его официальные релизы. Проверено
побайтово: сертификат из `TMessagesProj/release.keystore` в оригинальном репозитории
идентичен сертификату подписанта ассета релиза `1251`.

```
sha256 = 1a05a230b7d3c4703c79a5baf872396112669c4d716474be6f9e8247a54c4563
serial = 15055BB4
valid  = 2024-09-13 .. 2036-09-10
alias  = chen_hai
```

Поэтому APK отсюда **ставится поверх вашего текущего Nagram XF без удаления** —
совпадают и имя пакета (`fork.risin42.nagramx`), и ключ подписи.

Проверить любой файл вручную:

```bash
python3 tools/verify_signer.py NagramXF-v13.2.1-37a3538\(1252\)-normal-arm64-v8a.apk
# OK: signed by the official NagramXF release key   (exit 0)
```

## Ограничения и риски

- **Задержка.** «После каждого коммита» на практике означает «в пределах часа после
  готовности сборки»: 14–30 мин на сборку оригинала, до 30 мин на наш cron,
  15–60 мин возможной задержки планировщика GitHub, плюс интервал проверки Obtainium.
- **Не каждый коммит собирают.** В оригинале `paths-ignore` отсекает изменения
  `**.md` и `.github/**`.
- **Две ветки — два потока.** `dev` → Staging build, `canary` → Canary build.
  Одна работа может попасть в обе с разным SHA. Подписывайтесь на одну.
- **Стабильность.** Это `dev`, не релизы. Примеры свежих регрессий:
  [#205](https://github.com/Keeperorowner/NagramXF/issues/205),
  [#196](https://github.com/Keeperorowner/NagramXF/issues/196).
- **Play Protect** может ругаться: см.
  [#105](https://github.com/Keeperorowner/NagramXF/issues/105).
- **Зависимость от nightly.link.** Этот сервис проксирует публичные артефакты Actions
  без авторизации; сам файл он отдаёт с родного хранилища GitHub
  (`productionresultssa*.blob.core.windows.net`), а не со своего. Подмену исключает
  `verify_signer.py`. Если nightly.link умрёт, воркфлоу начнёт падать — заметно сразу.
- **Если оригинал перестанет собирать**, nightly.link продолжит молча отдавать
  последнюю успешную сборку. Воркфлоу пишет предупреждение в job summary,
  если сборка старше 14 дней.
